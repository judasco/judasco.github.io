### Introduction

For me, ICS 314 was the gateway into software engineering. In my previous ICS classes, most of the programs I created only ran in the terminal. They worked, but they felt limited because there was no real interface for users to interact with. In this class, everything changed. Instead of just writing programs that printed output to the console, I was able to create actual websites and applications for real users to use and interact with.

At first, the amount of new technologies introduced in this class felt overwhelming. We learned TypeScript, React, Next.js, PostgreSQL, Bootstrap, GitHub workflows, testing frameworks, deployment tools, and more. However, as the semester continued, I started to understand that these technologies were not just random tools. They represented the foundation of modern software engineering and taught me how professional software projects are actually built.

More importantly, ICS 314 taught me that software engineering is much more than just coding. It involves collaboration, project management, design, planning, testing, and communication. The topics that stood out to me the most were User Interface Frameworks and Agile Project Management because they completely changed how I think about software development.
<br>

### User Interface Frameworks Changed How I View Development

One of the most important topics I took away from this class was User Interface Frameworks. Being introduced to tools like Vercel, Next.js, React, and Bootstrap completely changed my understanding of website development. Before this course, I honestly did not realize how modern websites were built or how much structure existed behind them.

React especially stood out to me because of its component-based design. Instead of writing one massive HTML page, we could split the interface into reusable components that made the code cleaner and easier to manage. Bootstrap also helped simplify the design process because it made creating responsive and organized layouts much faster. Next.js introduced me to a more professional way of building web applications by combining frontend and backend functionality into one framework.

One of the coolest parts of the class was learning how data could be stored and dynamically displayed on websites. Connecting databases and displaying real information on pages made the projects feel much more realistic and interactive compared to anything I had built before. It made programming feel more creative because I was no longer limited to terminal applications.

I can definitely see myself using these technologies outside of class in the future. For example, I could create a website for a store I work at, design a portfolio website, or even develop tools that solve small real-world problems. This class showed me that software engineering can directly create products and experiences that people actually use every day.
<br>

### Agile Project Management Taught Me How Teams Actually Work

Another major lesson I learned from this class was Agile Project Management. Before ICS 314, I mostly worked independently on programming assignments. The final project was one of the first times I experienced what it was like to develop software as part of a team.

Using GitHub Projects, issues, milestones, and backlogs taught me how professional teams organize development. At first, these tools seemed small or not as important as coding itself. But over time, I realized they are foundational skills for real-world software engineering. Without proper organization and communication, even talented developers can struggle to complete projects efficiently.

I learned how to divide work among team members, assign responsibilities, and track progress through GitHub issues. I also learned the importance of communication when working collaboratively. Sometimes coding itself was not the hardest part of the project — coordinating tasks and making sure everyone stayed on the same page was equally important.

One thing I appreciated about Agile development was how flexible it was. Instead of trying to complete the entire project perfectly in one attempt, we continuously improved the application step by step. This made large projects feel much more manageable. I now understand why Agile Project Management is widely used in the software industry because it helps teams adapt to problems and changes throughout development.

Even outside of software engineering, I think the collaboration and planning skills I learned in this class will still be useful. Knowing how to communicate clearly, organize work, and contribute effectively within a team are important skills in almost any career.
<br>

### Software Engineering

Another important thing this class taught me was what professional software engineering actually feels like. In earlier programming classes, assignments were usually short and completed individually. In ICS 314, projects became larger, more connected, and more realistic. There were many moving parts that had to work together: frontend design, backend logic, databases, deployment, testing, and collaboration.

This class also taught me the importance of writing maintainable code instead of simply making code work once. Through coding standards, GitHub workflows, and reusable components, I learned that software engineering focuses heavily on readability and long-term maintenance. Real projects are not just written once and forgotten. They constantly evolve and improve over time.

I also gained more confidence as a programmer throughout the semester. At the start of the course, many of the frameworks and tools felt intimidating. But after repeatedly practicing and building projects, I became much more comfortable learning new technologies and solving unfamiliar problems. That experience showed me that software engineering is a continuous learning process.
<br>

### Final Thoughts

Looking back, ICS 314 was one of the most important classes I have taken so far because it introduced me to what software engineering is actually like beyond simple programming assignments. The course helped bridge the gap between writing code in the terminal and building complete applications for real users.

The lessons I learned about User Interface Frameworks completely changed my perspective on modern web development, while Agile Project Management taught me how software teams collaborate and organize projects effectively. More importantly, this class showed me that software engineering is not only about technical coding skills. It is also about communication, teamwork, planning, design, and adaptability.

The skills I learned in this course will definitely continue to help me in the future, whether I am working on personal projects, internships, or professional software development jobs after graduation. ICS 314 did not just teach me how to build websites, it introduced me to the broader world of software engineering.
